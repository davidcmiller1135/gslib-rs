## D-003: Where the oracle runs
- Status: decided
- Topic: harness.md
- Question: Should GSLIB run in CI, or offline with committed fixtures?
- Options: committed fixtures plus a pinned recipe; build GSLIB in every CI
  run; committed fixtures plus a scheduled regeneration job.
- Decision: **committed fixtures plus a pinned recipe.** (The recipe's
  location, originally `tools/oracle/`, is superseded by D-008: a Rust
  `xtask`.)
  The recipe downloads GSLIB, verifies a pinned checksum, applies output-format
  widening, builds with double promotion, runs the reference cases, and writes
  fixtures with provenance. Tests compare only against committed fixtures. A
  scheduled regeneration job may be added later.
- Rationale: CI stays fast, offline and deterministic (`AGENTS.md`, *Deterministic
  and isolated*); provenance is explicit; GSLIB source is never committed
  (D-002).
- Consequences:
  - Format widening is done by generic rewrite rules in the recipe, not by
    patch files, because patch hunks contain GSLIB source lines (D-002).
  - Committing GSLIB-computed *outputs* still needs the licence check in D-002
    before the first fixture lands.
  - The recipe needs gfortran wherever it runs, plus network access to
    gslib.com (blocked in this session's environment today).

- Decision: **Rust `xtask`**, invoked as `cargo xtask oracle --archive PATH

  - a `cargo xtask` alias in `.cargo/config.toml`.

  None of these is a dependency of `gslib_rs`, so the library stays lean.

## D-010: Comparing deterministic outputs
- Status: decided
- Topic: harness.md
- Question: What does "matches" mean for a deterministic program?
- Options: per-quantity tolerances with justifications; one global tolerance;
  ULP-based comparison.
- Decision: **per-quantity tolerances, each justified:**
  - structure must match exactly: row and column counts, variable names, and
    which entries are missing/UNEST;
  - direct formulas (variogram values, transforms, model evaluation) default
    to a relative error of 1e-12;
  - linear-solve results (kriging estimates and variances) are bounded by
    k · cond(A) · ε, with the harness computing cond(A) of each system;
  - a case may override a default only with a written justification in
    `case.toml`;
  - failures report the maximum absolute and relative error and their
    location.
- Rationale: tolerances reflect where the error comes from (`AGENTS.md`,
  *Differential and fixture tests*). A single global value would hide
  regressions in exact formulas or flag well-understood solver differences.
- Consequences: 1e-12 and the constant k are **initial values**, to be
  calibrated on the first fixtures and fixed by a new decision entry. Never
  loosen them quietly (`AGENTS.md`, *Never weaken … to get green*). The
  harness needs a condition-number estimate (e.g. from nalgebra's SVD).

## D-011: Statistical parity for stochastic programs
- Status: decided
- Topic: harness.md
- Question: How is statistical parity judged for `sgsim`, `sisim`, `sasim`?
- Options: ensemble vs ensemble; each implementation vs the model;
  two-sample distribution tests (KS/AD).
- Decision: **ensemble vs ensemble, plus independent invariants:**
  - GSLIB and gslib-rs each generate N realizations of the same case (N = 100
    on a small grid to start);
  - compared: ensemble means of the experimental variogram per lag, histogram
    quantiles, and data reproduction at conditioning nodes;
  - each difference in means must be within 5 standard errors, estimated
    from both ensembles;
  - separately, gslib-rs ensembles must reproduce the input model and
    histogram, so agreement with GSLIB is never the only check.
- Rationale: compares behaviour without needing identical random streams
  (`AGENTS.md`, *Parity levels*, *Statistical tests*).
- Consequences:
  - Fixed seeds make every outcome exactly reproducible, never flaky.
  - With about 50 comparisons per case at 5σ (≈ 5.7e-7 two-sided each, if
    near-normal), the chance of a false failure per case is about 3e-5.
  - N and the grid size set fixture size. Keep each stochastic fixture under
    ~2 MB; a larger fixture needs a decision entry.

## Finding F-004: setrot and cova3 checked against the vendored source
Read from `vendor/gslib-2.0/src/GSLIB/SETROT.FOR`, `GSLIB/COVA3.FOR` and
`GAMV/GAMV.FOR` (2026-11-27):

- **`setrot` matrix: matches gslib-rs exactly.**
  - `alpha = (90 - ang1)` (or `450 - ang1` at 270° and above), `beta =
    -ang2`, `theta = ang3`.
  - All nine `rotmat` entries match `geometry::Anisotropy::new` term for term.
  - `afac = 1/max(anis, EPSLON)` with `EPSLON = 1.e-20` (the clamp; ours is
    an explicit error, as in ROADMAP §2).
- **Divergence: π.** `DEG2RAD = 3.141592654/180.0` in `setrot`, and `PI =
  3.14159265` in `cova3` (hole effect). gslib-rs uses the exact value.
  Relative angle difference is about 1e-10: relevant to exact-stream parity
  and to the 1e-12 default tolerance (D-010).
- **Dip sign: negative is downward (z up).**
  - `GAMV.FOR`: "dip … measured in negative degrees down from horizontal",
    with `declin = 90 - dip` measured "positive down from vertical (up)", so
    a direction's z component is `sin(dip)`.
  - `setrot`'s arithmetic agrees: positive `ang2` tilts the major axis
    toward +z.
  - `SETROT.FOR`'s comment "the dip of the ellipsoid measured positive down"
    contradicts its own code; trust the code.
- **`cova3` structure types:**
  - 1 spherical, `1 - hr*(1.5 - .5*hr*hr)` with `hr = h/a`;
  - 2 exponential, `exp(-3h/a)`;
  - 4 power, `cmax - cc*h**a` with `PMX = 999.` added to `cmax`, `h` not
    divided by `a`;
  - 5 hole effect, `cos(h/a*PI)`.

  All match gslib-rs.
- **BUG in gslib-rs: type 3, Gaussian.** GSLIB computes
  `exp(-(3h/a)*(3h/a))`, i.e. exp(−9(h/a)²); gslib-rs had exp(−3(h/a)²). At
  h = a, GSLIB's Gaussian reaches 1 − e⁻⁹ ≈ 99.99% of the sill, not 95%.
  Fixed with a regression test.
- **Divergence: coincidence test.** `cova3` returns `cmax` (the nugget
  applies only at zero distance) when the **squared anisotropic** distance
  is below `EPSLON = 1.e-10`, i.e. within about 1e-5 in rotated, scaled
  units. gslib-rs uses Euclidean distance below 1e-10. Recorded in ROADMAP
  §2; exact parity needs a policy for it.

## Finding F-006: vmodel parity (plan step 4, 2026-11-27)
From `VMODEL/VMODEL.FOR` and the first fixtures (8 cases in
`tests/fixtures/gslib/vmodel/`):

**How `vmodel` works** (read from the source):
- **Points:** for `il = 1..nlag+1` it evaluates
  `(il−1)·(sin(azm)cos(dip), cos(azm)cos(dip), sin(dip))·lag`, with
  `DEG2RAD = 3.14159265/180`.
- **The repeated row:** row `il = 1` is written twice; the second evaluates
  `0.0001·offset` but prints the first row's `h`.
- **Columns:** the fourth is `ndir`, not the direction index;
  `gam = maxcov − cov`.
- **Power structures:** `a_hmax` holds ω, and `anis = a_hmin/ω`.

**Results** (worst |Δ| ÷ sill, with the cause):
| Case | Worst | Cause |
|---|---|---|
| Spherical, exponential, Gaussian isotropic; anisotropic along the axes | ≤ 1.4e-16 | machine precision |
| Power without nugget | 1.1e-13 | GSLIB's `maxcov − cov` includes `PMX = 999`, costing ≈ ε·1000 absolute |
| Anisotropic, rotated | 4.3e-12 | `setrot`'s π = 3.141592654; derived bound ≈ 1e-9 |
| Hole effect | 8.974e-9 | `cova3`'s `PI = 3.14159265`; derived bound cc·(h/a)·3.59e-9 = 8.97e-9 at h/a = 2.5, which the measurement matches |

**GSLIB defect: the power model loses its nugget.**
- `COVA3.FOR` adds `cmax` (which contains `c0`) once per power structure, so
  `gam = maxcov − cov` cancels the nugget.
- Measured: GSLIB's γ is `cc·h^ω`, and gslib-rs's minus GSLIB's is exactly
  `c0 = 0.1` (±6e-14) at all 42 points with h > 0.
- gslib-rs keeps the nugget (`AGENTS.md`, *Do not treat legacy agreement as
  proof of correctness*). Case `power_with_nugget` documents the defect as an
  expected deviation.
- Not yet checked: whether nested power structures (each adding `cmax`)
  compound it.

**The harness catches the bug it was built for:** restoring the pre-F-004
Gaussian formula makes the vmodel test fail with 63 mismatches.

## D-015: Calibrating the default tolerance for direct formulas
- Status: decided
- Topic: harness.md (R7, D-010)
- Question: D-010's default of 1e-12 for direct formulas was provisional.
  Does the evidence support it?
- Options: keep 1e-12; tighten towards the measured errors; loosen.
- Decision: **keep 1e-12**, applied relative to the sill for variogram
  quantities.
- Rationale: every vmodel case without a documented π divergence measured
  ≤ 1.4e-16, except power at 1.1e-13 (explained by `PMX`). That leaves
  margin without hiding real errors: the Gaussian bug alone produced 63
  failures. The two π cases need explicit, derived overrides, and have them.

## Finding F-007: nscore and backtr parity (plan step 5, 2026-11-27)
From `NSCORE/NSCORE.FOR`, `BACKTR/BACKTR.FOR`, `GSLIB/{NSCORE,BACKTR,GAUINV,
GCUM,POWINT}.FOR`, and 6 fixtures.

**How GSLIB does it:**
- **`nscore`:**
  - trims data outside `[tmin, tmax)` (writing −999 for them) and drops
    weights ≤ 1e-10;
  - perturbs each datum by `acorni·1e-6` (F-005) and sorts;
  - assigns `gauinv((cp + oldcp)/2)` with `cp += w/twt`;
  - the second pass reseeds ACORN identically, so each datum is looked up
    at exactly its own table node.
- **`backtr`:**
  - the interior is `powint(..., 1.0)`, linear in score space;
  - tail option 1 is linear in **probability** between `(0, zmin)` and
    `(gcum(y₁), vr₁)` (lower) or `(gcum(yₙ), vrₙ)` and `(1, zmax)` (upper);
  - the result is clamped to `[zmin, zmax]`;
  - `tmin`/`tmax` are read but never used.
- **`gauinv`** is a rational approximation ("Kennedy & Gentle 1980, p. 95",
  per its own comment); it returns ±1e10 for p < 1e-10 or p > 1 − 1e-10.
- **`gcum`** is a polynomial approximation to Φ, exactly 0 or 1 for |x| > 6.

**Measured accuracy** (dense grids, against gslib-rs's exact functions; the
tests in `harness/src/gslib_math.rs` re-derive both):
- `gauinv`: at most 1.501e-8;
- `gcum`: at most 7.458e-8 absolute, with relative error in the tails up to
  1.6e-3 near x = −4.5.

**Results:**
| Quantity | Worst | Fully explained by |
|---|---|---|
| nscore scores (smooth, skewed, weighted) | 1.498e-8 | `gauinv`: GSLIB's own arithmetic with ported `gauinv` reproduces its table to ≤ 1.8e-14 |
| nscore table values | 9.79e-7 | despiking (< 1e-6, and always ≥ the datum) |
| backtr interior | 8.9e-18 × range | machine precision |
| backtr tails | 1.58e-4 absolute | `gcum`: GSLIB's tail formula with ported `gcum` reproduces its output to 1.4e-16 × range |

**Ties:** in the `ties` case, scores are declared expected deviations. The
order of distinct values and the despiked table values still match.

**Mutation checks:**
- using the cumulative endpoint instead of the midpoint in
  `normal_scores`: 384 mismatches;
- dropping the lower-tail scaling in `BackTransform`: 11 mismatches.

Also verified: the standard-normal constants in the `transform.rs` tests
agree within 4.4e-16 with Python's `statistics.NormalDist` (CPython 3.13).

## D-016: Tolerances and explanation checks for nscore/backtr
- Status: decided
- Topic: harness.md (R7)
- Question: How should results that go through GSLIB's approximations
  (`gauinv`, `gcum`) be compared?
- Options: loosen a global tolerance; per-quantity bounds derived from the
  measured approximation error; port the approximations and compare against
  GSLIB-as-ported.
- Decision: **both of the last two:**
  - compare gslib-rs with GSLIB using derived bounds:
    - scores: absolute `GAUINV_MAX_ERROR` = 2e-8;
    - table values: absolute 1e-6 (despiking);
    - backtr interior: 1e-12 × (zmax − zmin);
    - backtr tails: absolute `span·2ε/(p_edge − ε)` per point, with ε =
      `GCUM_MAX_ERROR` = 7.5e-8;
  - **and** run an *explanation check*: GSLIB's own formula, with the
    ported approximation, must reproduce GSLIB's output at the direct
    tolerance (1e-12).
- Rationale: a bound alone shows a deviation is small enough. The
  explanation check shows it has the stated cause, so a real bug can't hide
  inside an approximation's tolerance.
- Consequences:
  - The bound constants are pinned by tests that fail if they are exceeded,
    or are more than twice the measured error, so they can't quietly become
    loose.
  - The ports are test-only: gslib-rs keeps exact functions (ROADMAP §2).
  - Use this pattern wherever GSLIB uses an approximation.
